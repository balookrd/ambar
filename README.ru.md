# ambar

[English version](README.md)

`ambar` — CSI-драйвер Kubernetes для реплицируемых томов на небольших кластерах
k3s. Репликацию выполняет модуль ядра DRBD 9; сам драйвер задуман как один
бинарь на Rust, запущенный как DaemonSet.

## Состояние

Интеграция с Kubernetes ещё не написана. В репозитории лежат дизайн, то, на что он опирается, и агент узла:

| Часть | Состояние |
|---|---|
| Спека | написана, в конце шесть открытых вопросов |
| Образ с собранным модулем DRBD 9.3.4 и drbd-utils 9.35.0 | собирается, есть тесты |
| Стенд: три ВМ Lima с k3s | скрипты в `stand/` |
| Опыты с отказами DRBD 9 на стенде | записаны с выводом команд |
| CSI-драйвер (агент на Rust) | ядро без Kubernetes: модель тома, файл ресурса, разбор статуса, загрузчик модуля, локальное согласование через CLI; проверено на стенде |
| Замеры на целевом железе (NanoPi R5C) | не сделаны |

На боевом кластере ничего из этого не запускалось.

## Что заложено в дизайн

- У тома `replicas: N` копий на N узлах (N не меньше 2). Остальные узлы
  подключаются к тому без диска, поэтому под запускается на любом узле.
- При `protocol: C` запись подтверждается после того, как она легла на диски
  всех узлов с копией.
- Том монтирует один узел (`ReadWriteOnce`, `ReadWriteOncePod`).
- Данные тома — разреженный файл на локальном диске узла, подключённый как
  loop-устройство с прямым вводом-выводом. Переразметка диска не нужна.
- Модуль DRBD собирается заранее под точную версию ядра и лежит в образе;
  компилятор на узлах не нужен.

## Требования для образа и стенда

| Что | Значение |
|---|---|
| Хост | macOS на Apple silicon |
| Lima | 2.3.0, `vmType: vz` |
| Docker | `docker buildx`, `linux/arm64` |
| Ядро, под которое собран модуль | `6.12.116+deb13-arm64` (штатное ядро Debian 13) |
| Для `image/build.sh` на хосте | Rust stable 1.95 или новее (`rust-version` крейта), `cargo-zigbuild`, `zig` и цель, добавленная командой `rustup target add aarch64-unknown-linux-musl` (проверено с zig 0.17.1 и rustc 1.99.1) |

## Сборка и проверка образа

Команды выполняются из корня репозитория.

```bash
image/build.sh
```

```bash
image/test.sh
```

Ожидаемая последняя строка:
`OK: ambar-drbd:dev module 9.3.4 for 6.12.116+deb13-arm64, drbd-utils 9.35.0`

```bash
image/test-loader.sh
```

Ожидаемая последняя строка: `OK: 6 loader cases`. Этому тесту не нужны ни
Docker, ни ядро Linux.

## Проверка агента

```bash
cargo test
```

Ожидаемая строка: `test result: ok. 291 passed`. На стенде агент проверяет
`stand/agent-smoke.sh`, см. `stand/README.md`.

Запуск стенда описан в `stand/README.md`.
